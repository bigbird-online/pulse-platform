# PULSE 唯一事实入口与整体替代合同

WI018；2026-10-13。状态：R1/R2/R4 的第三轮审查修复已在 Muse 采用；R3 全局旧写者退出尚未完成，不代表全局替代或人类 UAT 验收。
本合同补足原规格的替代终点，不把 WI550 的局部自用等同于 WI018 完成。
现场与反例见 [2026-10-13 验真记录](../../pulse-space/memo/2026-10/wi018-integration/audit-20261013.md)。

## 1. 替代终点

生产业务事实只由既有 `github.com/bigbird-online/PULSE` 的 `refs/heads/main`
在 `pulse-production` 身份下接纳；所有生产业务写入口进入同一核心。
旧 SQLite、YAML、Relay WI 绑定、工作区登记和 ComputeCost 查询库不能分别裁定
同一个事实。过渡适配只解释历史，不是永久可选的第二写入路径。

唯一权威不等于把一切字节塞进 Git，或由 SCL 接管操作系统：

| 内容 | 唯一来源与责任 | 可重建/观察关系 |
| --- | --- | --- |
| WI 定义、执行授权、任务、候选、人审、效果意图与观察 | 核心生产事实日志 | Relay、YAML、Stats、登记表只投影；不能回写决定 |
| 目标/基线、产出贡献、反馈、人的参与声明与修正 | 同一核心的类型化观察事实入口 | ComputeCost 保存的查询库必须可从这些事实重建 |
| 前 WI 讨论事实 | 同一事实设施中无执行权限的 context 记录 | 以后仅追加 context↔WI 关联；不为计量创建假 WI、Graph 或启动执行 |
| 用量观察与归属 | Host 验证原生来源、稳定事件身份、边界、数量和覆盖后接纳 | 计量区间是证据边界；重复来源核销，真实新调用仍新增，不重复复制成两笔用量 |
| Pi 原文、人类原始输入、私密证据 | 受管私有保管者；日志仅含摘要、大小、访问级别、取得方式 | 不以压缩或编码规避隐私边界；缺证据不使已接纳业务事实失效 |
| 进程、GitHub 发布、实际文件、渠道送达 | 真实外部系统 | 核心保存带时间和身份的观察，不把缓存当当前物理事实 |
| 程序版本、工具链、凭据、主机策略 | 正式部署和主机配置入口 | 不产生另一套 WI 状态；版本指针本身不是业务账本 |

ComputeCost `UsageLedger` 的原子追加、去重及计算可复用，但不得继续成为目标、
产出、反馈的唯一持久来源。`sources.json` 可用于连接配置，不能决定另一业务权威。
旧数据迁接须保留来源、时间、原身份和缺口；不能先删库再宣称投影可重建。
核心观察入口不得要求任务执行 grant、计量基线或重复人审；Host 身份与来源校验保留。

## 2. 窄接口中的恢复责任

外部接口继续是 `execute / inspect / resume`。以下复杂性必须由核心及正式 Host
适配器封装，不交给 Agent 猜存储格式、换 request_id 或手动拼接进程身份。

1. **计量不干预执行。** 采集超时、无完整行、末端倒退、缺价、缺库、导入失败均不能
   撤销工具、阻止派发、停止/收尾、交棒和接续；对应计量明确 partial/unavailable。
   不吞掉身份错误，也不把缺失用量填成零。继承 WI550 已验证的解耦，不另写一套。
2. **提交未知不同于拒绝。** 未知结果保留原 request_id 和已固定输入，通过原请求
   读回解决。消费端不能因新的 toolCallId 默默生成替代请求。已证明原请求提交的读回
   不能被兼容投影修复失败推翻；投影修复属于可重试派生工作。
3. **依赖局部化。** 只校验本次消费的事实路径及声明依赖。无关 symlink、可执行文件、
   旧 WI 的坏 YAML 不能冻结其他 WI。列表明确列出不可读条目和覆盖；绑定查询不得
   用“跳过坏记录”伪造唯一性。跨 WI 约束使用可从事实重建、并回指原事实的索引。
4. **有界重试且说明真实原因。** 无关 Git 提交只重建发布，不重复业务决定；预算耗尽
   与真实依赖冲突分别说明。原意图、尝试、已知副作用和未知结果均保留。
5. **证据故障分层。** 已接纳事实重放不依赖私有字节可读。新增事实若必须保全批准
   原文/固定候选证据，不能直接吞掉保管错误后声称已保存；应复用已证明持久的原来源，
   或返回明确可恢复的保管错误和原请求。可选计量证据失败仅影响计量。禁止退回 Git
   原文、宽松 chmod、临时未登记旁库；ACL、属主、跨节点保管和备份须一起验证。
6. **派发成功不等于工作完成。** 独立核验的 assignment、candidate、Session 保持。
   断线/重启后根据真实进程与原会话结果判断 running/interrupted/completed/unknown；
   若已中断且原责任未完成，正式 resume 入口恢复同一核验。不得把存在 session 文件
   或已 ACK 当 verdict，不重派第二个核验，不伪造人审或调用者身份。
7. **外部效果不无限循环。** 累计尝试、退避、下一可行动步骤由原意图推导。未知结果
   先观察，不盲发；终态保留未结责任，不用失败次数自动改成成功或删除。

发布包、测试归档不应作为每次业务决定的整包副本。优先引用已有受管不可变产物，
固定来源/内容摘要和可取得位置；只有有耐久性和权限证明后才能退出旧内嵌表示。
1 MiB 分块解决单个 Git blob 上限，不等于无界归档增长已解决。

## 3. 旧权威退出清单

R1–R4 各交付一个可观察的闭环。任何未通过项阻止声明 WI018 全局替代完成。
兼容读取可保留；生产旧写入必须退出，不能仅更改目录、代理类或增加配置开关。

读取、接纳和执行授权分开：导入旧候选/旧效果不授予当前执行者身份；终态原样保持。
旧数据库与 Git 差异逐项根据原发布/原决定解释，不用一种状态直接覆盖另一种。

## 4. 整合顺序与责任边界

- **R0（本次准备）**：冻结主干和 WI550 源码组合，复现反例，固定此合同与测试矩阵。
  报告中的数字必须标时间；当前事实不得引用旧自动化摘要冒充实时状态。
- **R1（WI018 核心/Relay）**：继承 WI550 计量解耦，解决未知请求与读写隔离、核验
  同会话恢复。第一闭环是当前中断核验能正常续办；不代替其给出通过 verdict。
- **R2（统一事实接口）**：核心接纳包含前 WI 在内的类型化声明；复用 WI550 的
  计算、去重、查询、Stats 与 skill。旧 UsageLedger 内事实先保全迁接，再变成只读
  导入源及可重建投影；禁止两条线并发改 Muse WI550 工作树。
- **R3（完整替代）**：各类旧状态承接与所有真实消费者接入；封闭旧写者和分配器，
  清偿/保留明确归属的原效果。入口缺失报告真实能力缺口，不静默 fallback。
- **R4（实验节点整体采用）**：将通过前述门的精确代码合入 main，正式 CI/CD 生成
  Relay/Core/ComputeCost/Stats exporter/skill 一致的集成发布。包含 WI027 单一 CC
  凭据源修复。Mac Stats 构建与 Muse exporter 采用分别验证。

TCloud 保留已有真实 UAT。不得依据旧自动化提示继续排除 Muse，或把两节点版本当成一致。
第三轮验真与修复边界见 [2026-10-14 记录](../../pulse-space/memo/2026-10/wi018-integration/audit-20261014.md)。
既有 TCloud CD 同时采用核心、Relay、
ComputeCost、Stats exporter 和固定版本技能；沿用原来源登记、会话、cron 和生产 Git。
切换先确认并停止原空闲 Relay，再更新核心和观察事实来源，最后启动并读回父进程与
实际 profile。历史计量原批次经过完整校验后有界批量发布，保留原摘要和顺序；中断
后复核已发布事实再继续；不同节点的本地批次编号不是全局事实身份，按原事实去重，
保留原字段与冲突，不要求各节点有同一个本地事务前缀。查询按事实内容指纹流式读入，
不因无关 main 提交重解码，不重复持有全部原始 JSON。
冷读的 Git 子进程数量不得随计量批次数或分块数增长。一次固定快照使用有界内存的
管道读取，逐一核对对象摘要、批次链和事实领域；不把全部对象暂存到临时盘。读者可接续
自己保存的已验证前缀（见 ComputeCost 协作契约“已验证前缀检查点”）：仅当 Git 对象指纹
仍相同时跳过该前缀，后续批次照常校验并链接到前缀摘要；否则完整读取。
部分读取、校验失败或提前关闭读取器均不能授权在未确认的观察流头部追加。
安装/回滚只在有界协议门内检查唯一权威与候选支持的存储格式，不全量读取业务历史或
计量流；完整历史语义重放另列验证证据。安装回执不能宣称未执行的全量重放通过。
回退保留能读取已采用事实的核心和来源登记，不能恢复旧计量写者或删去原件。

源码集成使用 WI018 自己的受管工作树。Muse 已准备的 e451 候选、原核验与证据保留，
不在其正在操作期间切换组件。下一精确候选冻结后只做一次必要的可信验证；本机或
VM 上的 fixture 测试不能伪装为可信发布 CI。兼容安装必须包含原请求结果和在途
核验的旧 runner 合同，不能因新 bundle 改了 runner 字节而断掉旧会话身份。

## 6. R3 承接与封闭的实现合同（2026-10-14）

先完成承接，再关闭旧入口。切换是节点正式安装合同，不能按 Agent 的运行时绕回旧写者。
Pi、CC、Codex 只在 Host 身份与输入读取上不同；共用 execute/inspect/resume 和同一生产日志。
Host 校验已登记可执行文件、当前祖先进程、原会话和原始用户记录；命令不得选择 actor、
session、surface、策略文件或传入授权布尔。非 Pi 用量缺口只影响计量，不影响业务工具。

历史接纳必须分别保全：原执行/资源授权、冻结候选与原人审、协作 ACK、全部效果意图及尝试。
保存原件不等于已转换：新读模型须暴露原候选、原批准和未结义务；后续普通操作能消费它们。
接纳不能要求所有原效果先在旧写者结清。已发送或结果未知的原效果先观察，不重发；只降低
依赖它的发布/终结能力。缺失或互相冲突的原件返回具体恢复入口，不补造完成或批准。

旧 writer 退出包括稳定 CLI、Relay CC/Pi、编号器、SQLite 间接效果表、YAML 写者和异步
Broker/reconciler。正式安装记录这些边界和真实消费者；只配置新入口而未封闭旧包不算退出。
历史数据库保持只读；全部业务新增和恢复决定进入新核心。部署失败允许回退程序，不能
重开已退休旧 writer 或撤销已接纳事实。关闭前必须通过历史待验收、悬空效果、非 Pi 三类
反例及普通保存、接续、发布和终态资源清理的组合测试。

### 日常 rollover 完整合同（R3 实际入口反例）

Muse 生效的 323cb82c 包中 `/wi rollover` 被 parser 拒绝，核心已有的显式
`rollover(target)` 不代表普通用户入口完整。修复必须由同一个 Host 控制器处理
原渠道输入、源会话让出、新建真实后继、核心接续、渠道采用；人类不提供内部 Session。
核心先记录源会话转交并封闭旧执行权，实际后继经 Host 原生进程/文件证明后方可接续。
私有 Host 记录只保管原请求和进程/会话身份；是否提交、谁有权限均从 Git 核心读回。
创建失败、提交未知、进程重启和重复命令须恢复原转交，不能生成第二个后继或重复授权。
计量缺失不能影响任何一步。Pi、CC、Codex 入口及旧会话保留须分别集成验证。


## 7. 冷切换与生产态验收提案（2026-10-14）

依据人类本轮提出的五条标准，采用一次有界冷切换，结束长期双写者兼容。
2026-10-14 人类已授权先执行准备与演练，改为 ownermac 首发，符合预期后再到 TCloud、Muse。
本节不表示已经执行切换、批准任一存量 WI 的取消，
也不表示七天真实稳定窗口已经完成。原有修复和生产事实继续保留。

### 五项完成门

| 门 | 可核对的生产态标准 | 必须保留的证据 |
| --- | --- | --- |
| P1 单一入口与同版收敛 | ownermac、TCloud、Muse 使用同一 main 提交与固定组件/skill 版本的发布清单；各平台产物分别校验。Pi、CC、SDK、独立 Codex、CLI、自动化的 WI 创建和业务状态变更均进入同一新内核，无旧写者 fallback。操作系统文件维护不被扩张成 SCL 授权范围。 | 每节点安装及实际加载摘要；真实入口创建/保存/查询/接续的证据；旧入口负向验证。仓库 HEAD、指针或进程健康不能替代实际加载。 |
| P2 旧写者退出 | 第 3 节的 17 类权威逐项记录唯一新权威、真实消费者、退出方式和反向验证；生产分发物删除旧 harness 业务写命令，不加载旧决策器。旧内核与数据库仅可只读归档，旧绝对路径、残留进程、cron/Broker 不能继续写入或发布。 | 17 项退出矩阵全部有证据；旧进程/命令/间接写表及发布路径拒写，同时新入口正常完成业务。保留的只读适配器没有决策或写回能力。 |
| P3 旧执行责任清零 | 以冻结时的权威快照枚举全部非终态旧 WI，不把“约 21 个”当成已核对数；明确覆盖 duke 615、aki 520 和 WI018 自身。逐项选择同 ID 迁接，或依据真实完成/取消/停止决定受控结清。未完成不得改成已完成；冻结候选、人审、资源、未知副作用、源代码与会话均保留。 | WI 处置清单含来源摘要、原状态、责任人、处置依据、新核读回、未结外部效果归属。零未处置旧 WI、零无人负责的在途效果、零有效旧执行权；不是所有业务 WI 都被关闭。 |
| P4 发布纪律与真实稳定性 | 首次冷切换先隔离验证和回滚演练，再由 ownermac 首发并承担 24–48 小时真实灰度；随后相同候选推广并在三节点同版下连续真实使用 7 天。后续候选仍遵循同一灰度流程。不得以空闲时间、CI 或重复健康检查累计完成。 | 普通任务及长任务/错误/重启/rollover 的真实过程；零平台卡死、零人工改账/重建/恢复。长任务有实际进度，超时有界且沿原请求恢复；平台阻塞缺陷修复后重计稳定窗口。不能仅凭缺少灰度认定某次故障根因。 |
| P5 计量单一事实来源 | Host 将经校验的用量和声明经新内核接纳；ComputeCost 从这一事实流计算，Stats 消费其同水位投影，不保留本机独立业务/计量权威。允许可删除重建的查询缓存及有界传输暂存；私有原生证据仍在受管保管处，不能复制原文到 Git。 | 从同一固定事实水位重建查询投影与 Stats 等价；重复观察不双计、真实新调用仍新增、缺失明确为 partial/unavailable。断网/采集/价格/投影故障不能减少工具、阻塞派发或接续。 |

P1 的同版要求针对完成态。灰度允许登记过的短期版本差异，但只允许验证兼容的
新内核版本共同写入。首次跨旧/新协议冷切换时，其他节点的旧写者必须冻结；不能
让 ownermac 写新协议的同时让其余节点继续旧协议写入。若需连续服务，可将业务临时
承载于 ownermac；恢复其他节点须完成同版与原状态读回。选择维护窗口和承载安排时，
应展示对具体 Agent/渠道/调度的影响，不能暗中让其停工。

### 有界切换顺序与回退语义

1. 完成新入口、17 项退出路径、历史读取和普通工作全链路；冻结一个精确发布候选。
   先形成逐 WI 处置表及在途副作用表，再执行任何存量终止决定。
2. 演练停写、冻结水位、同 ID 接纳、重复执行、断点恢复和回滚。检查新的查询投影
   可重建，历史私有证据可取得；不要求 Agent 手工拼接内部会话身份。
3. 在有界维护窗口停接新业务写入、排空或保留原请求，冻结所有旧写者和调度写路径。
   固定生产 Git ref、旧本地已提交未发布尾部、原会话与在途效果身份；有不一致先解释。
4. 按逐项处置计划让新内核接纳原事实或记录真实退役决定。只读归档保留原始摘要；
   旧数据库、原分支和新生产日志的来源链可核对，不能以清库或 reinit 代替迁接。
5. 只启动 ownermac 新消费者，读回业务/原请求/工具/计量/渠道；符合预期并经过真实灰度后，先后推广
   同一候选至 TCloud、Muse，再进入三节点七天稳定窗口。全部门满足后才称为生产态。

回滚只回退可读取当前事实格式的程序版本，不回退生产事实、不恢复旧写者、不让旧
内核重新解释已接纳的新决定。尚未发生新生产写入时可中止准备阶段；一旦新写入已
接纳，没有已验证兼容的回退版本就必须保持停写或向前修复，不能宣称“旧包能启动”
等于回滚可用。首次切换的回退方案也必须包含这条限制并事先演练。
