# Continue original production execution

An existing active WorkItem resumes through the installed native `resume`/`review_existing_execution` entry. The same authenticated Pi session, original execution epoch, existing resource allocation, decisions, checkpoint and candidate are retained. No reinit, new WorkItem, start, invented scope or repeated business approval occurs.

The Host reads only its operator-registered historical kernel root. The current lineage is decoded as data; the old controller is never invoked. Original state, authority, registration bytes and connected operation/checkpoint/effect records are captured as one private immutable input. Production Git audit receipts must authenticate the latest state, operation and registration fence. Older SCL may have published later receipts on its registered WI branch. This is accepted only as an original input from the same production remote: the current main fence must match, all main receipts must remain byte-identical, and the observed branch commit and receipt hashes are sealed into the new main journal. The branch never becomes the current state authority and its business commits are never merged by this admission. Unpublished changes, conflicting or revoked authority, another session/surface/actor, pending effects, unsupported candidate semantics and redirected physical paths fail closed with a concrete recovery reason.

The core accepts that evidence once into the same production Git journal. Subsequent authority is derived only from this journal; removing or changing the historical source cannot revoke or alter accepted facts. The existing old-writer production boundary rejects a WorkItem after native admission. Reading or deployment preflight never admits it. Retries use the original continuation identity and cannot create another execution epoch or grant.

Physical workspace identity comes from the digest-bound original registration and live Git common-dir/branch/worktree checks. Existing paths and commits are preserved. Logical resource names are a deterministic representation of those exact original allocations, never caller-supplied widening. Original checkpoint and execution metadata remain readable, and inherited resources use the same capture/publication/retirement consumers with their original physical identity.

New workspace naming rules do not apply to retained allocations. A flat `WI-agent` path or another historical layout is accepted only through that same audited original registration; the inherited resource binds its exact parent and basename. Session, actor, surface, scope, realpath, account ownership and live Git registration checks remain mandatory. No directory move, replacement registration or repeated human approval is required.

Verification covers the real historical shape: original Pi session and two repositories, restored scoped work and checkpoint, unchanged epoch/candidate/worktree, same-request retry, a second independent Git client, journal replay after removing the old source, source/registration/fence tampering, wrong native session, pending effects and read-only policy. The installed interface is exercised without calling the real UAT conversation or writing its business state. Publish through main and the existing TCloud CD, then read back exact installed source and consumer binding. Human-channel UAT remains user-owned.
