# agent-harness 验收规格

## 1. 验收方法

本文件的 A 编号定义新验收场景族。[功能规格](project-requirements.md)每条 AH 必须有对应的新实现、断言和结果证据。下表规定的是验收方法，所有实现与运行状态初始均为 **not_run**，不得把场景存在当作已通过。

基础环境为新核心、隔离事实存储、确定时钟/身份以及明确可观察的外部适配器。自动测试不加载旧 `tests/`、fixture、conftest 或旧状态机。外部适配器模拟可以证明本地规则，不能代替安装和真实消费者验收。

## 3. 统一故障矩阵

阶段至少包括 Draft、已采用图、执行中、候选待验、负面验真返工、已批准待交付、终态待清理和迁移中。每个适用阶段施加以下故障，不为每个阶段实现独立恢复器：

| 故障 | 注入对象 | 保持不变的性质 |
| --- | --- | --- |
| 全量投影删除 | 声明的缓存/登记/账本/队列/发布临时树 | 同一 WI、原决定、原请求和有效权限；正常入口可重建 |
| 损坏、旧代、合法伪造 | 单个及全部派生输出 | 不能影响内核决策；无需人工选可信副本 |
| 提交前后退出 | 事实事务及原请求响应边界 | 零次或一次决定，可读回原结果 |
| 外部发送前后退出 | attempt 与真实适配器边界 | 不以无回执证明未执行；未知先读回 |
| 竞争与迟到 | 领取、修改计划、人审、撤权、重建发布 | 一个合法决定；旧结果不能套用新对象 |
| 网络和运行入口故障 | Git/Host/渠道/验证者 | 本地可用能力继续，依赖该动作的能力如实降级 |
| 容量/权限故障 | 状态、缓存和安装目标 | 不假报 durable；可证的读能力保留 |

组合测试优先覆盖真正交叉的事务边界，以有限可重放序列生成方式运行并保存失败种子。不得复制大量只改文件名的测试，也不把简单功能全部乘以无关故障。

## 4. 历史与支持矩阵

迁移样本至少覆盖：未启动 Draft、标准执行、lightweight 执行、已升级、待验候选、负面验真、人审批准/豁免、终态、跨机迁移、部分发布、未知发送及旧输入缺失。只使用隔离副本；保留 provenance 和原始摘要，不修改生产 WI 以制造测试数据。

支持矩阵逐项记录 OS/Host/渠道、安装制品、实际可用能力、调用命令/输入、结果和限制。macOS 与 Linux、Codex/Pi/Claude Code、Telegram/飞书不能互相替代通过。原有只读/移交面不被标成执行面。

## 5. 证据与交付判断

每条 AH 的实现报告包含代码位置、对应 A 断言、自动结果、所需真实消费者结果，以及 `not_run / failed / passed / not_applicable`；not_applicable 仅适用于该消费者不具备的能力，不能用于删除整个必需功能。复用一个运行结果覆盖多个 AH 时保留各自断言，不能按测试数量推导覆盖。

总交付要求：全部 AH 有通过证据；接口清单无未分类遗漏；新架构依赖边界通过；旧写者已实际退出；已声明支持面安装/采用成立；Spec、README 和 skill 一致。源码提交、模拟适配器、CI 或单一 Muse 旅程均只是其中一类证据。
