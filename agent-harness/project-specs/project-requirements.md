# agent-harness 功能规格

## 1. 地位、范围与基线

本文件规定替换式重写的目标行为，与 [架构](project-architecture.md)、[验收](project-acceptance.md)、[质量规范](project-standards.md)共同约束新实现。`specification` 表示规范已写出，不表示代码、安装或验收已完成。实现范围是 agent-harness 的全部现有公开能力及下列用户确认的协作流程；不重写模型运行时、消息网关或其它产品。

需求依据按优先级为当前用户明确指令、已确认业务契约、可验证的实际消费者需求。源码主基线为 PULSE main `e6ae6e2463d834dec0d2dda16f8d9e25adf62bfe`；WI018 已确认改进参照 `2245ef600141cecb8f8c394b0106cbcdd9c85ed5`。旧代码、旧测试和旧 Spec 用于发现能力，不要求新实现复刻它们的状态机、文件布局或故障绕行。后续 main 变化按功能差异登记，不能无条件重新引入旧控制链。

下文每个 AH 编号是必须实现的功能义务；A 编号指向独立验收场景。同一场景可以证明多个义务，但必须逐条记录断言和证据。功能清单不是运行时账本，不能成为 WI 的第二权威。

## 2. 产品不变量

- **一个 WI，一个当前权威内核。** 多个协作者可在授予的范围内工作；所有生命周期决定仍进入同一个提交边界。执行容器、负责人、协作者、验证者不是多套状态写者。
- **决定来自意图，状态由内核导出。** 客户端不能提交任意下一状态。原请求、准入输入、决定、业务事件和必要外部动作在一个本地事务内接纳。
- **派生物可全部丢弃。** 删除、损坏或滞后不能改变业务事实、产生新授权、重复执行外部动作，亦不能要求人类对账。需要的视图由正常入口自动重建。
- **结果分层而不分叉。** 本地决定、外部发布、消费者采用和资源退役分别如实表示；后几项未完成不撤销前一项。完成必须满足对应业务契约。
- **保留独立事实。** 人类原始决定、成果、独立回执、实际工作区、外部执行尝试及结果不是缓存，不从派生状态猜测或制造。
- **Agent 自行处理机械故障。** 人类只决定目标、价值、范围和新的授权；有效授权不因视图故障要求重复确认。

| AH-014 | 必需执行节点结束后，正常推进自动安排 UAT；不得要求 Agent 手工调整多个 status。开始验证、验证通过、最终批准、交付完成是不同事实。 | A-09 |
| AH-015 | 已采用计划保留采用人、时间、阶段、原文和摘要。同请求重放不重新采用；显式检查新文件才比较文件内容。不同计划必须经版本修订，不能覆盖原采用。省略 WI 时仅允许唯一明确绑定。 | A-07 |
| AH-016 | lightweight 使用同一内核和事实模型，可直接处理边界清楚的工作，不强制补标准图、独立验证者或重型结算仪式；仍保留来源、范围和必要证据。 | A-04 |
| AH-017 | 快捷完成须写 WS，满足自身验收与适用的交付、资源义务。所需人类确认沿原决定消费；不把标准流程门禁整套搬入快捷流程。 | A-04 |
| AH-018 | lightweight 可升级 standard，保留原 WI、已完成工作、执行者及历史，补齐图和方案确认后进入标准路径；不重新创建或伪造最初 Draft。 | A-10 |
| AH-019 | 流程类型不能成为逃避当前验收或未决责任的工具。已升级的标准流程不能通过改标签走轻量收尾；启动类型和当前类型分别可读。 | A-10 |

## 5. 成果、验真、批准与返工

| AH-021 | 独立验证绑定原候选、被指派者、职责、授权范围和证据载体。验证者与生产者身份独立；本地已提交指派和 ACK 不等待 Git 副本一致即可生效。 | A-09 |
| AH-022 | 接纳 accepted、partial、blocked、rejected 等明确结果，保存原回执与逐项证据。错 WI、错候选、伪造身份或变造原始证据不得成为当前验证结论。 | A-09 |
| AH-023 | 人审批准或要求修改均绑定确切候选和真实决定来源。批准旧候选不批准新成果；同一批准重试不新增决定，不能用 CI、安装或生产者自述代替人审。 | A-11 |

| AH-026 | 标准完成要求当前候选的有效验真/明确豁免、人审、声明的交付及必需消费者结果成立。必需责任未结清时不得完成；终态事实只提交一次，并明确资源清理是否完成。 | A-13 |

## 6. 责任、执行权和连续工作

| ID | 必须满足的行为 | 验收 |
| --- | --- | --- |
| AH-027 | 区分成果负责人、执行者、请求协作者和独立验证者。完整责任转移、部分委派、仅请求三种语义明确；委派不得隐式改变 owner。 | A-14 |
| AH-028 | 支持指派、接受、拒绝、撤回、重派和多人接收；每次明确由谁作决定，保留原合同和原因。必要责任是否结清由内核裁定，不通过改 HO YAML 实现。 | A-14 |
| AH-029 | 执行权绑定真实调用者、资源范围、操作范围和代际。冲突命令由唯一事务边界串行裁定；旧代际、错误主体或越界资源不因缓存可读而取得写权。 | A-15 |
| AH-030 | 范围内协作者可并行执行，互斥资源不能重叠授予。一个权威写者不等于所有 Agent 只能串行工作；执行权撤销后新的结果接纳按原尝试和撤销事实判断。 | A-15 |
| AH-031 | Host 提供真实 Session/runtime/surface 和当前入口；普通人类不填写内部摘要、opaque ref 或恢复阶段。身份定位故障与没有授权分别返回。 | A-16 |
| AH-032 | checkpoint 原子保存最小充分进展、决定、引用、风险及下一步，保留历史。默认交接摘要至多 32768 UTF-8 字节，大材料用版本化引用；不能复制完整聊天、秘密或原始提供者身份。 | A-16 |
| AH-033 | continue 在同一 WI 读取当前事实并继续有效工作；已终态或等待验收时提供相应观察/下一步，不强行恢复业务写权。不依赖旧 ledger、网络或旧 Session 在线。 | A-16 |
| AH-034 | rollover 保存进度并交给新 Session，原执行者失效后后继才能接管；启动新进程不等于接续已成功。默认不按猜测的 token/成本自动切换，策略启用沿已有明确授权。 | A-17 |
| AH-035 | 跨主机迁移保留原 WI、事实、输入版本及在途请求，源端先封存并失去写权，目标才取得新代际。同迁移重试不产生第二个后继；网络分区不能凭旧副本自授新写权。 | A-17 |
| AH-036 | 人类可明确改变授权、接管或重建当前 WI。新决定不以损坏的派生登记或原执行者批准为前提；普通恢复复用现有事实，只有明确要求改变目标/前沿才替换有效定义。 | A-18 |
| AH-037 | 支持释放、撤回、归还范围授权，保留原操作及责任；清理资源不是授权来源，过期授权不能借恢复命令复活。 | A-14 |
| AH-082 | Agent 身份与入口分离：任何入口（Telegram、飞书、ChatGPT、Codex 应用、命令行）的会话都可代表任一已登记 Agent，前提是可信绑定方签发的会话绑定。身份三元组的 `surface` 指安装节点；入口是会话属性，随原生来源记录，统计按 Agent 汇总并可按入口分组。 | A-37 |
| AH-085 | 同一 Agent 跨入口接续：调用会话与持有会话属同一 Agent 时，`/wi continue` 凭该条人类输入把执行权一步转到当前会话，原会话代际失效，有效范围授权随转；不同 Agent 仍走交接或接管。 | A-38 |
| AH-087 | 同一 Agent 其它会话追加记录：WI 执行中时，与持有者属同一 Agent 的其它会话可提交 `checkpoint` 与 `record_work`，代际取当前读回值，范围限于持有者自身可写范围（WI 资源内、不含已委派授权）。持有者与代际不变；领取、交接、结束、改计划、授权等其它意图仍只属持有会话。记录保存作者会话，公开观察不显示。 | A-40 |
| AH-088 | 跨节点协作按 Agent 指定接收方：请求与部分委派的接收方可只写 Agent，也可写完整会话三元组；两种都可在任一节点。只写 Agent 时，该 Agent 任一节点的任一会话可接受或拒绝，首个接受的会话成为承担会话，委派范围授权绑定该会话与当前代际；此后同一 Agent 的任一会话可归还或完成。写完整三元组时仍只有该会话可响应。接收方可以是发起方自己的 Agent（同一 Agent 跨会话请求或委派），完整三元组不得指向发起会话；请求方会话（发起会话，及同一 Agent 中当前持有该 WI 的会话）不能接受、拒绝、归还或完成该合同。完整责任转移仍限另一 Agent 的一个本节点确切会话，同一 Agent 内走 rollover。响应事件记录实际响应会话，公开观察不显示会话。接收方 Agent 的会话在列表与读取中看到待其响应或结清的合同；无人值守的 gate 可凭已安装程序只读读取某 Agent 的协作收件箱（最小字段），据此唤醒该 Agent。 | A-41 |

## 7. 工作区、发布和外部动作

| ID | 必须满足的行为 | 验收 |
| --- | --- | --- |
| AH-086 | 每个 WI 有磁盘限额，默认 1 GiB：effect service 测量该 WI 在每个受管根下的整个 WI 目录（`<受管根>/<WI>`）及其目录外未回收的登记工作区，同一字节只计一次（不跟随链接、不读文件内容，共享 Git 对象与平台发布不计）；未经 allocate_workspaces 登记的副本也计入，测量结果按登记工作区与未登记路径分列，inspect 列出未登记路径并提示删除或改用 allocate_workspaces（稀疏）。受管根外由 Agent 自建的仓库副本同样计量：取 Host 仓库的全部 Git 工作树，并在每个 Agent 工作区内找含 `.git` 的目录（worktree 与 clone，含 `clone --shared`；最多 6 层，不跟随链接），两种来源一律排除内核分配的工作区（受管根内、`harness/` 分支）、任一 WI 登记的工作区路径与源检出；副本归落在其工作区内的 Agent，或分支以 `<Agent>/` 开头的 Agent（扫描到的副本读其 HEAD 取分支）；分支或路径恰好指名一个现存 WI（完整 ID，或唯一以 `_N` 结尾时的 `wiN`）的副本记为该 WI 的指名副本，计入 WI 限额；其余为该 Agent 的未归属副本，记在它持有的每个 active WI 上，按每 Agent 2 GiB 限额定级（不可调高）。Agent 副本是否参与拦截由开关 `quota.AGENT_COPIES_ENFORCED` 决定，默认只观测：照常记录并显示其将导致的等级，不拦截。发现失败、Agent 工作区内目录不可读、任一 WI 日志不可读或副本不可读时该测量作废，从不删除副本。每台主机只量本机磁盘，测量按主机分别记录，一台主机的测量只替换它自己那一份，是否入账按该主机自身的等级与用量变化判断，不同主机的相同测量是各自的请求，WI 等级取各主机最近记录中最严重者；不带主机的旧版测量只更新一份共享的旧记录，不能解除按主机记录的拦截，下一次按主机的测量取代它；只在等级变化或用量变化超过 10% 时记入日志；达到 80% 为预警；超限时拒绝开启新工作的意图（开始工作、计划、领取、记录工作、授权、分配/修订工作区），收尾、交付、发布、回收、终止与读取不受影响；记录进展（checkpoint）、发起协作求助与只缩小稀疏检出的修订工作区（新路径全部落在当前路径之内）仍可执行，已准入的修订效果可执行完，使超限的 WI 能自行释放空间；清理后重新测量即解除；调高单个 WI 限额须人类决定；未测量或测量失败不拦截。 | A-39 |
| AH-038 | 工作区分配/登记绑定真实仓库、受管路径、分支、资源用途与范围。登记视图可重建，但真实 Git 身份、越界路径和他人占用不可被覆盖。共享人工根中的未归属修改保留。 | A-19 |
| AH-039 | 支持同 WI 多仓库、稀疏范围、范围扩展/收缩、授权迁移及替换；变更由一个资源意图完成，结果可重试，不能要求旧副本摘要逐字段一致。 | A-19 |
| AH-040 | 读取和发布针对确切源版本与已接纳输入，成果快照可审计。临时发布目录不成为新业务源或第二工作区权威；可变日志需先截取获准的固定证据片段。 | A-20 |
| AH-041 | 保留 Git 集成、来源收敛和人工修改结算能力，明确实际执行范围。远端拒绝、dirty/diverged 或唯一未发布成果必须保留，不自动 reset、clean、force-push 或吞掉冲突。 | A-20 |
| AH-042 | 投递目标由统一的业务策略和原请求决定；main-only、租户/命名空间和服务仓库的边界保持。补齐本地视图不能重算已发送请求的目标。 | A-20 |
| AH-043 | 外部动作先记持久意图，发送尝试和回执也进入事实记录。待执行队列由这些记录生成；重建队列不丢失“可能已执行”信息。 | A-21 |
| AH-044 | 外部结果未知时沿原请求读回；不能因缺少本地回执换身份重发。只有证明未发生或下游支持原幂等键才重试；不可判定时保留 unknown，不宣称恰好一次执行。 | A-21 |
| AH-045 | 本地决定、工作与 checkpoint 不同步等待 Git/网络/其它节点。外部失败只降低依赖该动作的能力；已提交决定不因投影或发布失败回滚。 | A-21 |
| AH-046 | 响应逐项说明本地读写、业务执行、外部发布、交接和终态结算能力。pending/unknown/conflict 不合并成一个泛化 blocked；下一步由内核事实确定。 | A-22 |

## 8. 持久性、重建和恢复

| ID | 必须满足的行为 | 验收 |
| --- | --- | --- |
| AH-047 | 同 request_id 与相同语义输入返回原决定；同键异意图明确拒绝，未提交失败不冒充成功。请求身份不绑定可丢弃视图的摘要或不相关 checkpoint。 | A-08 |
| AH-048 | 命令准入、合法迁移、决定与必要外部意图原子提交。调用者不得提交任意 next_state；不得先写某份业务 YAML 再让内核采用。 | A-23 |
| AH-049 | 持久事实日志及其原始输入是重放依据；状态索引可重建，不能独立更新。日志损坏与缓存损坏分别处理；无法证明的事实不从缓存猜出。 | A-23 |
| AH-050 | 同一确定修订生成完整派生视图。删除、损坏、替换、陈旧及不存在的缓存均由正常入口自动重建，无逐字段对账、人工 repair 或新增决定。 | A-24 |
| AH-051 | 投影重建可中断、幂等，不能让半代视图成为权威。读操作可直接从事实重放得到结果；不能为了重建缓存先要求缓存中的登记或权限完好。 | A-24 |
| AH-052 | 历史候选、已发布审计和当前执行视图区分。较晚发布时间、旧派生文件和当前时间戳不改变原决定，旧交付请求不能覆盖更新的本地事实。 | A-20 |
| AH-053 | 磁盘满、只读目录、权限失败和损坏制品有明确行为：保存成功才称 durable；无法写入时仍提供可证的读取与交流。预留容量只用于必要持久操作，不无限重试或新增 WI。 | A-25 |
| AH-054 | 查询注明来源、修订及实际新鲜度；unknown/stale 不显示健康、完成或零值。公开投影不泄露凭据、原始提供者身份及非授权会话正文。 | A-22 |
| AH-055 | 安装、升级、启动与回退验证精确制品，沿原安装事务恢复。运行入口不依赖可编辑源码和旧项目环境；诊断不得修改封存安装内容。 | A-26 |
| AH-056 | 旧数据一次性导入保留原身份、决定、顺序、输入和未知状态。导入成功后不再读取旧副本作决策；源封存与目标激活保证不会出现两个可写内核。 | A-27 |
| AH-057 | 终态清理保留审计、原始证据和唯一成果，退休工作树/分支/登记及可丢弃发布目录。业务完成与资源退役分开可读；未知外部执行结果不能随清理删除。 | A-13 |
| AH-058 | 终态读取和合法交付不要求重新激活生产者或重做人审；同一终态重试不追加完成事件，不恢复 execution grant。 | A-13 |

## 11. 运行时失败的统一分类

| 分类 | 正常响应与动作 |
| --- | --- |
| 派生视图不可用 | 直接重放事实并自动重建；业务结果不变，不产生新决定 |
| 命令语义/权限冲突 | 无业务 mutation，说明冲突事实及可行下一步；不修文件来放行 |
| 原始输入缺失/变造 | 保留已有事实，拒绝接纳该输入；不能从当前草稿补造历史 |
| 已提交但响应丢失 | 使用同请求身份读回原决定；当前状态从最新事实读取 |
| 外部结果未知 | 保留 attempt，先读回原动作；只限制依赖该结果的推进 |
| 事实存储不能持久写入 | 不宣称提交；可证的只读/交流仍可用，恢复容量后继续同请求 |
| 事实存储损坏 | 使用验证过的原始备份/迁移包恢复；没有可靠来源时保持 unknown，不使用派生缓存充当事实 |
