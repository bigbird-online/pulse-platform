# Hestia 资源事件接收与承接

资源探针通过本机正式 CLI 提交 oikos_resource_alert/v1。接收命令只在已声明 resource_alerts 的 Hestia policy 下工作，核对执行方、设备白名单、三轮故障确认或持续容量观察字段。未知字段、错误身份、未映射 policy、损坏或非私有事件状态一律拒收。

接收只证明事件进入现有 heartbeat runtime 的持久队列，回执明确 queued，不能声称模型已执行、问题已修复或创建了 WI/Handoff。事件不进入 canonical ledger，不更改 SCL 执行权，不创建新调度器。已有 scan/dispatch 扫描该队列并由原 Hestia policy 决定自治或升级。

同一活动问题重复提交复用原事件；崩溃后原事件可读回。消息处理完成必须由 Hestia 通过正式 resolve 命令提交当前事件摘要、处置结论与证据引用；queued 不计完成，deferred 保留在队列。损坏事件产生显式 critical hit，不能清空或报正常。修复后新的同类故障可以再次进入队列。

资源输入是现场资料，不能授予生产变更或生命周期权限。执行者必须重新核实当前节点、消费者及在途工作；未知、物理介入、认证或高风险情况沿原升级路径处理。不得根据事件自动重启 Muse、回退 WI018、读传秘密或伪造接单。

验收：覆盖两类真实 probe payload、重复/中断/损坏/链接/权限/未知设备与身份，证明真实扫描 hit 和既有 dispatch policy 匹配；发布并采用后，再验证本机正式接收、真实 Hestia 承接回执与生产探针映射。源/CI 成功不计生产采用。

现有 P0 五分钟检查可调用 resource-alert dispatch --background；空队列不启动模型，忙碌锁不重复派发，工作进程沿原 dispatcher 的平台准入、工作区活动保护、失败预算和升级路径执行。该命令只派发资源事件，不恢复已停用的旧 cron 或扫描其他 WI。worker_started 只证明进程启动；处理结果仍以事件自身正式处置回执为准。CLI exit 0、提交或通知不覆盖尚无处置回执的事件；连续无回执沿原失败熔断处理，事件保持待处理。

派发产生的 Git 可见事件追加通过现有 broker settle-ledger 保存，业务处置与台账发布完成分列。派发前先恢复唯一绑定原资源事件、原服务端点的未完成台账交易；失败保留原交易和追加，不重派发、不另建交易。派发正常退出或抛异常后都结算实际已追加事件。已跟踪事件即使匹配 ignore 仍须验证追加；已忽略且未跟踪的历史运行归档保持原位，不属于这次 Git 变更。所有可见的未知文件、非事件改动、重写或无效事件继续拒绝，不能为了发布事件清理历史归档。Broker completed 只证明原端点发布与读回，不代替四端源码收敛。

`deferred` 有合法持久证据时仍属于未完成业务，不能称缺回执或计执行器失败。本轮执行须产生不同于执行前、时间不早于本轮开始的新处置回执，旧 deferred 不能让空执行通过。后续扫描安全读回合法 deferred 后显示 `blocked_resource_deferred`、`owner_review_required`，保持 pending 并静默等待原处置事实变化，不再自动重跑；原 failure_count/circuit 历史保留，不生成 covered 或伪终态。缺失、损坏、未登记设备和 queued 无处置回执仍走原失败保护。只有真实 resolved/escalated 回执才结束原事件。

资源专用会话固定使用派发时的实际 Harness 根和声明的 heartbeat runtime 取证目录。仅核验资源、调用原升级与正式 resolve，不要求 Git /wrap、提交、创建 WI 或在共享 .harness/evidence 写过程文件；临时写范围收窄到本轮资源取证目录，不扩大既有业务权限。模型正常退出后只以可安全读回的 resolved/escalated 处置回执计执行成功；缺失、queued、deferred 或损坏回执不计通过。原非资源会话的提交门不变。

原服务台账交易在准备提交前超时，若远端仅沿原历史前进、原事件前像仍逐字相同、现场冻结摘要和身份未变，可在同一交易中绑定新远端并续期。保留原事件追加及交易身份；已准备/发布、事件变更、历史分叉或现场漂移继续拒绝，不另建交易代替。

仅修改服务台账续期、发布、原服务恢复路由及显式 prepared 恢复方法，保留原方法签名、交易结构和全部原测试并追加声明恢复用例时，CI 通过 AST 比对选择 Muse service-ledger 检查，完整执行 Broker、资源事件发布和 CI 分流契约；运行时安装、升级及回退契约由其对应改动触发。其它 Broker 方法、模块、生命周期、依赖、原测试变更或混合范围继续使用完整检查。

原服务事件已准备但发布失败时，由原 resume-service-ledger 入口恢复同一交易。重新校验现场冻结摘要、原事件完整追加证明、准备工作树身份与洁净状态、提交父项/路径/模式/字节以及远端历史。已到达远端的原提交只读回后收尾；尚未发布且远端沿原历史前进、事件前像不变时，在私有准备树合并远端，原提交保留为父项，并先持久化精确恢复意图。合并提交后中断可按同一意图读回；原交易、原事件和旧源码检出保持不变，正常发布与精确收尾完成后才报告落账。未知文件、现场追加、远端事件改写、历史分叉、准备树漂移及非服务权限继续拒绝，不通过通用状态跳转解锁。

事件发布保留返回码、固定诊断类别以及 stdout/stderr 的散列，不保存任意输出、远端地址或秘密。发布超时或读回失败保持原交易待恢复；重试先查询实际远端效果，不因进程失败重复事件。实际 Git 拒绝仍须修复其原因，恢复入口不绕过认证、保护或授权检查。

原发布入口在每次 push 与远端读回前，必须在原 Broker 外部状态的 owned 0700 目录以 no-follow 目录句柄保存并 fsync 不可变 intent，再保存同 attempt 的独立 0600 result。只记录固定 phase/stage、原交易与目标/预期 authority、exit/timeout/errno/duration、输出长度/散列和固定诊断类别；不保存 raw stdout/stderr/argv/env/token、未知异常文本或远端地址。初次 authority 查询、已发布读回、发布后的读回失败都须留证，不新增交易状态或发布权威。旧按交易覆盖的诊断写入口迁移至该不可变证据；已有历史文件保留。intent 失败禁止新 push；push 后 result 失败保留原交易待恢复，不盲目二次发布。原锁、CAS、恢复合同、事件及秘密保护不放宽，诊断不追造历史首次发布失败原因。
