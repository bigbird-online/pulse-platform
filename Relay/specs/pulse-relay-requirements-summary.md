## 一、决策演进时间线

### 5/5 — PULSE 平台尽快上线
- 飞书 BOT > CC CLI，教学顺序反转
- 斜杠命令第一版（/model, /new, /compact），优先图形界面版
- 上下文空间监控功能降级，等 1M+ 模型
- **PULSE 价值 = 接入强模型**，当前 GLM 只是形式上能通

### 5/8 — GLM interactive 模式 bug + 多 BOT 路由
- 语道发现 Relay bug：GLM 必须用 -bear（interactive）模式，不能用 -p（print），否则被限流
- 检测逻辑：base URL 是 GLM → 自动走 interactive 模式
- 所有 BOT 全部路由到 Amanda → 修为不同 BOT 对应不同 Agent
- **P0：合并语道 bug 修复**

### 5/12 — 算力 = PULSE 核心使命
- "PULSE 的存在意义 = 解决会员能否稳定接入好算力"
- Relay 进展：流式输出 ✅ / GLM 模式修复 ✅ / 飞书卡片超时兜底 ✅
- 斜杠命令（含 /model）🔲 未做
- GLM 识图 vs OCR 路由 🔲 难产
- **PULSE 核心目标：稳定接入 Claude/Codex 类算力**

### 5/15 — 代码合并 + outbox 文件回传
- 飞书图片→CC ✅ / CC 生成文件→飞书（outbox）🔧 测试中
- 斜杠命令（含 /model）✅ 已 push
- 微信委托扣款 ⛔ 阻塞（官方未批准）

### 5/19 — 课件质量讨论（无 Relay 新需求）

### 5/22 — PULSE 定位=粘性工具，不是盈利工具
- 计费：支付宝支付+订阅功能作为兜底方案
- Agent 模板 + 算力接入 = 三大吸引力

### 5/26 — 算力池架构讨论
- **长征提议**：直接做算力池（不要多节点 Relay+CC），所有账号在一个池子里路由分配
- **语道限制条件**：
  1. 必须合法调用（CC -p / Codex -p，不能透传 API）
  2. CC + Relay 必须在同一节点上
- Relay 主备两个，CC 可以有多个节点
- 算力不是最着急的——**先上线 PULSE 平台**
- Harness → 改名为 ENG

### 5/29 — 充值模式 + 冷迁移
- 已改为充值模式，租户开通全通
- **开发中**：用户查看充值金额/余额/消费进度页面
- **模型切换**：国内节点多供应商，用户 switch model 切换，供应商对用户不可见
- **冷迁移**：放弃热迁移，节点账号不可用时通知用户 3-5 分钟后可用，自动迁移工作区+对话记录
- 语道建议：先用本地 GLM + 新加坡 CC 做模拟切换实验
- **Relay 费用设计**：官网价展示给用户 + 内部成本均摊，警告线+死线
- 小红书发布被警告 → 需改 Computer Use 方式

### 6/2 — 语道推翻计费方案
- **开发优先级三步走**：①把 Relay 程序搞好 → ②加国内节点 → ③加国外节点
- 语道核心批评："你自己都用不了，我也用不了，你去解决想象出来的卡点"
- **计费模式推翻**：充值+倍率+按量扣减 → **纯订阅制**，抄 ChatGPT
- 5 个供应商 key 已备齐（GLM×2 + 讯飞 + Kimi + DeepSeek）

### 6/5（最新） — 定价策略定调 + Agent→Skill 转向
- 模型切换功能演示完成（/model, /model auto, /model default, 多 key 池, 429 冷却）
- **定价策略定调**：
  - 按官网价卖，不赚 API 差价
  - 不提供跨模型自由切换，买什么用什么
  - 国内模型可 API 计费支持多个
  - 国外模型一个供应商一个套餐
  - DeepSeek 作为兜底池
  - 起步推荐 1-2 个模型（MiniMax M3 国内）
- **Agent 模板不如 Skill 重要**：
  - 不主推复杂 Agent 模板
  - Skill = 核心会员权益，每周更新一个
- **优先级重排**：①营销材料 #1 → ②Relay 完善 #2 → ③闲鱼试水
- Agent 模板转 Web 版本（OpenRouter 方案）——语道下周推进

## 四、语道的核心批评（避免跑偏）

1. **"你自己都用不了，我也用不了，你去解决想象出来的卡点"** — 先解决实际卡点
2. **"算力不着急，先上线平台"** — 会员可能国产模型就够用
3. **"不能给用户太多选项"** — 选项越多越难解释
4. **"第一分钟不赚钱，量上来后自然有利润"** — 先跑量再优化
