# CR-02：旧写通道隔离设计（历史分析，未实施）

> 当前范围以 [PULSE 全平台布局方案](pulse-platform-layout-plan.md) 为准。本文仅保留已发现的共享凭据风险，不要求另建通用隔离平台；实际旧写通道退役和其他业务权限保全仍须验证。

关联：`wi_20260823_184`、PR #466、[总体方案](agent-harness-unified-governance-plan.md)、[准入记录](agent-harness-migration-phase-a-readiness.md)。

## 人类范围与当前结论

2026-09-11 用户要求继续准备直到具备搬迁条件；承接此前明确的范围：允许凭据访问隔离设计及隔离演练，保留其他 CWA 业务能力。此记录是业务范围说明，不是机器授权凭据。生产停写、凭据变更、数据库搬运、数据发布权切换仍须 C/D 的真实人类授权。

A1 仍未通过。现有证据是旧 publisher 与 Relay 共享 UID/SSH agent，客户端 fence 可被旧版本绕过；尚无覆盖所有通道的远端拒写证据。不能把下面设计当作已部署能力。

## 要保证的真实行为

其他业务仍能提交合法 CWA 变更；任何能够运行旧 Harness 的业务执行身份，都不能获得可绕过检查的 CWA 写凭据。切权后，旧 Harness 数据路径不能再次成为活动写入目标。禁止旧写不能只依赖旧代码自觉检查。

仅新增一个 Harness UID、移除一个环境变量、停掉一个服务或撤销一把专用 key 均不够：同 UID 可读取文件/连接 agent、备用 GH token、runner credentials、SSH forwarding、远端代执行都可能恢复直接写权限。可任意执行源码的 Relay/runner 若继续保有原始共享写凭据，仍可运行旧 Harness。

## 首选方案与适用前提

优先使用经验证的远端强制规则覆盖旧 Harness 数据路径及全部写入主体；现有 API 403 不证明此能力可用，也不证明永远不可用。不得为获得它擅自升级套餐、公开仓库或扩大 token scope。

若远端不能落实，备选是**隔离凭据持有者并限制其写入请求**：

- CWA 写凭据只由独立、不可供业务执行代码的身份持有。该身份不能和 Relay、Harness 或任意代码 runner 共用 UID、SSH agent、HOME、可写服务配置或可修改的可执行物。
- 业务身份不再持有可直推的替代凭据，也不能经 sudo、容器 socket、通用远程 shell 或可改写任务启动器进入凭据持有者。
- 其他 CWA 业务保留提交能力，但通过受控发布入口；入口验证实际待写 Git 对象、仓库和目标 ref，而不是信任调用方声明的路径清单。
- CWA 活动 Harness 数据命名空间冻结后，入口拒绝其新增、修改、删除、重命名及改变其可达内容的 ref 更新。拒绝 force push、ref 删除、未准入 ref、tag/替代 ref 绕行、路径别名与未解析的对象；并发时重新验证当前目标基线。不得以事后 CI 或客户端 hook 代替执行前拒绝。
- PULSE 新写入口与 CWA 退役约束分开绑定；A 阶段没有生产 PULSE 写权提前开放。

这可能改变其他业务的发布调用方式，而不是取消其发布能力。必须先盘点并在隔离环境验证原业务的提交、PR 和自动化路径；不能为了 Harness 搬迁顺手改造所有业务，也不能在无法覆盖既有必需调用时声称此方案可执行。优先复用现有 Broker，只有查明其隔离与强制校验边界成立才复用，不能只把旧 push 包一层。

## 隔离演练必须验证的矩阵

演练使用合成仓库和一次性测试凭据，不复制真实 token、SSH agent 或 Host 私钥。不同身份必须由真实 OS 权限/独立隔离环境证明；Python mock、路径字符串和同 UID 的 chmod 演示不算权限隔离通过。

| 尝试 | 必须看到 |
|---|---|
| 旧版本直接 push；旧 fence 重启；并发提交 | 在凭据获取或独立强制入口被拒，远端受保护内容不变 |
| 读取 holder 私钥/配置、连接 agent、替换 holder 程序或服务配置 | OS/执行边界拒绝，且无原始凭据输出 |
| runner、Relay、cron 从继承环境或备用凭据直推 | 不存在未受控写路径；逐入口证明，不能用单节点结果覆盖三机 |
| 请求声称仅改普通文件，实际 commit 含旧 `.harness` 变化 | 依据实际 Git 对象拒绝 |
| rename、merge、force、删除 ref、替代 ref、并发基线变化 | 不能绕过受保护命名空间；重试不扩大授权 |
| CWA 非 Harness 的正常发布、PR 和重试 | 业务效果成立，无需把原始凭据还给业务执行身份 |
| holder 不可用、授权过期/撤销 | 写入失败可识别；正常对话与授权请求仍可进行，无虚假成功 |

## 进入 C/D 前还需提供

1. 每节点及 Actions 的主体→凭据类别→发布目标→强制拒绝位置清单，只记录安全元数据。
2. 不受任意业务代码控制的入口实现及独立审查，或可重复证明的远端规则。
3. 上述真实隔离负例、其他业务正例及故障恢复证据。
4. 精确生产变更对象、变更顺序、维护预算、撤回方式和影响说明，交人类批准。

若任意可运行旧 Harness 的主体必须保留无约束 CWA 直写能力，而又没有独立强制规则，则 A1 条件矛盾，必须报告不可准入，不能用更多客户端检查掩盖。当前不执行生产身份创建、权限调整或凭据撤销。
