# 全过程协作计量契约

适用 WI：wi_20261008_550。状态：联合重写候选契约，未作为已实现能力发布。
原 A1–A10 是业务验收；本契约落实 2026-10-10 大鸟确认的重写范围与设计委托。
现有 draft 计量只作参考：继承其真实事实，不继承其文件格式、阶段分组或统计结构作为产品约束。

## 1. 消费者与边界

大鸟与 Agent 从目标讨论开始工作，经真实协作入口保留产出、反馈和投入；后继仅沿原事务的正常恢复入口取得已知结果和缺项；ComputeCost 查询与 Stats 在同一截止、范围和口径下保持一致。

计量既不授予执行权，也不撤销、延迟或限制已有执行能力。WI 状态和授权只由已安装新核心依据唯一生产 Git 账本的原始输入与事实裁定；工具和主机权限由真实运行环境裁定。ComputeCost、Stats、缓存和旧计量状态不得改变工具列表、拦截调用、阻止启动/派发/接续/恢复，或成为封存、退役和正常工作的先决门。缺绑定、基线挂起、采集/写入失败、超时、滞后和已封存只影响相应计量结果，具体缺口保持 unknown/unavailable，不填零、不隐藏无关已知事实；原始事实保留并支持精确补采、重放与去重。

计量成功也不能增加权限。真实身份、当前核心 grant、主机资源准入、来源隐私和物理隔离校验保留；读取/保存不安全证据的拒绝只作用于该计量操作。人类已授权的独立主机维护不得为了计量另建 WI 或重复授权。计量不能改变 owner、代替原生身份、人审或独立验真。不新增业务审批链、通用工作管理系统、平行账本、持续用户打卡或无关 Stats 功能。

Feature risk=high-risk；纯模型定义切片为 normal。真实保存、计价、授权边界、展示和发布的改动均为 high-risk。

## 2. 计量从真实事务开始，不从编号开始

### 2.1 归属

- 无 WI 时，使用真实讨论来源与其有界活动范围标识当前事务；身份由运行时来源确定，不由 Agent 伪造 session 或预分配 WI。
- 后来正式创建 WI，只关联原事务及已记录事实，不复制事实、不新收一笔旧成本、不把产生时间改为关联时间。
- 同一会话可以涉及多个事务。以有证据的活动范围关联，不默认全会话属于最近 WI；未知、共享和有冲突的部分单列。
- 一个投入事实全局只保留一次原始数量；多个观察来源先核销重复。分配给多个事务的份额不得超过原量；无依据不均摊。
- 没有形成 WI 的探索仍保留其已有产出、投入和停止判断。没有编号不是丢弃条件，关联 WI 也不是计量成立的前置条件。

### 2.2 工作记录的最小语义

不再定义一套独立必经业务阶段。一次正常工作记录只补当时发生的变化：服务哪个目标、形成/改变什么、为什么修正、已有证据是什么。没有变化的已知背景只引用，不全量重复。

| 事实对象 | 必要含义 | 不得混同 |
|---|---|---|
| 目标及计量依据 | 要改变的现实、预期产出、单位/判据、初始基线、投入范围和适用观察期间 | 目标版本不是另一个 WI，也不是重新收费起点 |
| 产出与贡献 | 稳定对象身份、内容版本、本次形成/改进/复用的具体范围及来源 | 版本、截图、压缩包、发布副本不是新增整件 |
| 活动与投入 | 真实来源边界、发生时间、记录时间、可观测数量、用途解释及缺项 | 请求归属不是执行授权；用途判断不是时长实测 |
| 反馈与质量证据 | 作用于哪个目标/产出版本、原话或证据引用、修正理由、真实核验/验收决定 | Agent 声明存在不等于验收，批准旧版本不自动批准新版本 |

运行时保存原始来源与当时声明，ComputeCost 消费并进行确定性去重/计算，Stats 只读同一结果。继续复用已有持久事实设施；不得为实现这张表逐项创建新控制器、第二套生命周期或平行权威。

## 3. 产出计量

1. 按业务对象计，不按文件、调用、PR、测试或 WI 关闭数计。对象须能解释内容、用途、来源、归属和本次贡献。
2. 首次形成和改进分别报告；复用建立引用，不计为新增整件。对同一对象多次修正时，可报告期间改进范围，但不能自动按版本数加一。
3. 四类事实独立存在：产物已形成、针对准确版本的验证、真实人类接受、后续使用效果。不构造覆盖它们的单一“完成分”。
4. 期间形成以实际形成时间和该期贡献为准；期间验收以实际验收时间为准；当前累计是截至截止点的去重对象集合。这三种指标不能相加。
5. 不同类别、单位或比较口径并列；只有同单位和同口径的数量可以加总。已知子集必须附覆盖，不把子集冒充总产出。
6. 预期与实际的比较固定到目标版本。目标改变保留原投入与理由，普通纠错不重置目标或成本。
7. WI568 首次形成的 compute-wi-cost 与 WI779 的修改是同一能力上的不同贡献；WI550 的重写也是改进，不重新认领前两项工作的全部产出。

## 4. 投入、估值与覆盖

### 4.1 客观投入

记录全部来源中可观测的人类提交、完成主答复、进度消息、工具尝试、原生模型分项、作业执行范围；只按同一事件的多处观察去重，失败、返工、实际重试和计量自身工作不免计。

固定来源位置和截止点，累计快照不相加。一次归属修正改变引用或分配，不重写原始数量。先验证整个有界来源库存，再解释各段用途，不能只挑“有效工作”统计。

原生 Token 语义按来源解析并守恒；Pi input 不含单列缓存，reasoning 已含在 output。计价使用有来源、时间和摘要的 OpenRouter 标准模型价格，实际账单另列；缺价只令对应金额不可用。

### 4.2 人类投入

- 客观活动量、主动时间观测、估计区间分别表达。消息间隔、会话存续、等待和文本展示不能直接换算主动时间。
- 用途采用目标共创/判断、阅读、验收、协调、纠错/重复解释、恢复等可解释标签；类别是分析，不冒充人类确认。必要的共创和验收不一概视为浪费。
- 只在有明确依据时报告主动时间区间；无可用估计时继续显示活动量和缺口。不能以长期不可用完成 A3。
- 人类费率与收益估值没有依据时，不输出货币总成本或 ROI；有产出而无收益时仍报告产出与已知投入。
- 并行片段先去重。纠错、恢复、监督等是总投入的构成，不在总时间外重复叠加。

### 4.3 可信范围

每个量都携带事实/计算/估计/不可用类型、来源、时间范围、单位与覆盖。局部价格失败不隐藏 Token；缺少验收不隐藏产物；缺人时不抹掉活动记录；缺收益不抹掉产出。

## 5. 保存、接续与展示

- 明确区分 Agent 已声明、运行时已保存、ComputeCost 已消费、Stats 已展示，不用任意一层的成功代替另一层。
- 重试同一事实保持原身份；真实的新模型调用仍是新投入。消费失败从原持久位置恢复，不另造用量或重新签发验收。
- 正常接续读回目标版本、计量依据、产出身份/版本/贡献、反馈理由、已累计投入、最新消费位置及缺项。历史扫描只用于有界补缺，不作为每次接续步骤。
- lightweight 只处理真实发生的工作，不为计量补 Graph、人工报表或额外阶段。
- Stats 先呈现预期与实际产出，再看质量与投入。新增/改进/复用及期间形成/期间验收/累计分别可辨；明细可追到对象、WI 或前 WI 来源和证据。
- Stats 不重新计价、推断成果或维护另一份账本；列表、详情和汇总采用同一查询范围和截止。

回归优先覆盖：前 WI→draft→active 的只关联不收费；探索停止但有产出；一个 skill 跨 WI 改进；同物多版本/多载体；无验收或无收益仍显示；重复提交和真实重试；输入缺字段/价格缺失/身份冲突；跨会话与授权变化；同一时间窗口的列表/明细/汇总守恒。

## 7. 试验与判定

以 [measurement-basis](pulse-compute-cost-measurement-basis.md) 为唯一数值试验设定：5 分钟量级的负担判断、4 个校准片段、8 个独立验证片段、两次合计至多 4 分钟的有限核对，以及错误/漏测/开销门槛。设定是试验前的工程选择，不是已测性能。修改设定必须保留原试验及失败，不得事后择优。

自然工作不为样本量另造 WI。历史 568/779 为已知反例，不与未知自然样本混算。观察期从相应目标形成到验收或停止；比较必须同范围和可比质量，不以假想“旧方法零成本”作基线。

设计可进入实现不等于人时估计已经可用。发现持续人工拼账、负担抵消收益或有限探索仍无法得到关键量，按原停止条件返回价值/范围判断，不追加普遍监控或新治理系统。

## 8. 迁接与删除原则

保留已证原生解析、隐私边界、摘要/时间证据、去重、价格与守恒检查。重写以 WI 整项验收为中心的业务主模型与分叉查询，替换对应 Stats/skill 入口；旧源只读关联到新对象与贡献，不持续新旧双写或重复加总。

有义务交付的旧数据、有效历史结果和已有责任先验证可读，再退出旧消费路径。只有准确版本的源码、测试、默认分支、安装、实际加载和消费者结果一致，才声明替换完成。回滚不得删已发生事实。

## 9. 最小持久路径与接口边界

### 9.1 唯一计算事实库，不创建前 WI 控制器

采用现有 ComputeCost `UsageLedger.ingest_receipts` 的锁、原子追加批次、内容身份、修正链和知识水位，扩展其封闭事实类型。它保存计量事实，不签发执行权；SCL 原生产日志仍是工作项授权、任务、候选和人审的唯一权威。两者不是互相替代的 WI 账本，ComputeCost 不复制一套任务状态机。

前 WI 保存入口是 ComputeCost 的 `record-stage` 语义增量命令，而不是 `create_draft` 或 `start_work`。命令通过已登记运行时来源和受审原生 Host 采集适配器取得真实 actor、来源身份、边界与已存在材料；不得接受调用参数自报的 session、权限、用量或“已批准”。适配器在同一进程内使用受审 Host 捕获能力；不能把可伪造的 `identity` JSON 当认证凭据。生产目标库来自正式安装/来源登记，不接受业务参数任意指定路径。登记位置只取受审原生父进程启动环境中的 `PULSE_COMPUTECOST_SOURCES`：Linux 读 procfs，macOS 读同账户 `KERN_PROCARGS2`；调用进程环境不作数。

已有原生日志继续是原始证据；新增计量事实进入现有计量库，不增加 stage 文件目录、私有第二库或另一个重试队列作为常态。事后来源补缺只能使用登记的只读来源，保留 observed/declared 和历史缺口，不冒充执行当时的 Host 绑定。

### 9.2 最小数据约束

- `context_ref` 由 Host 为原始目标讨论的稳定来源事件生成不含私密原文的引用；它没有 owner、启动、资源占用或终态，不是无编号的第二个 WI。
- 事实信封保留版本、稳定事实/业务对象引用、发生时间、观察时间、生产者、证据引用、类型化值及可选前驱。入库批次时间由存储端给出。沿现有 Receipt 身份/修正规则扩展，不叠加另一套去重算法。
- 目标/基线、产出贡献、反馈、参与解释作为类型化语义增量；Host 只证明谁在何时作了声明，不能因此把其内容标成独立验真或人类确认。修正同一声明引用前驱，新发生的贡献/活动有新身份。
- 产出身份取规范对象/原来源，版本取真实摘要或发布标识；不同载体引用同一对象。跨 WI 的新增、改进、复用引用同一对象，其具体范围独立表达。
- 用量身份按原生事件及模型分项稳定生成；原生 SCL 区间和常规 Runtime collector（采集器）必须映射同一事件身份。原生区间摘要仅是证据，不另外成为一笔可加用量。旧聚合无法展开时列为尚未核销的证据，不与明细相加。
- 后取得 WI 编号，新增 `context↔WI` 关联事实；关联包含依据、适用活动集合及可信程度。跨会话由原 context 引用接续，不按 cwd/最近 WI 猜。确认和归属修正只改变读模型，不改原始 Token、产出日期或早期知识水位。
- 人类原话、Agent 分类、时间估计、人类自报、真实批准分别编码。批准仍读取 SCL 原决定；普通参与不需要 `record_attention` 式人类确认。原始私密会话不进入公开报告。

### 9.3 一次保存与失败恢复

`record-stage` 接受原 context（首次为空）、实际来源引用、语义变化和原修正引用；Host 补身份、截点和源证据。写入与去重在同一现有账本事务完成，返回规范事实引用和水位。提交结果未知时查原事实/请求身份，不生成另一身份重写；只有新工作才产生新事实。

语义保存不等待模型用量终结：原生运行时在最终答复、压缩或重试结束后通过既有采集路径追加实际用量，归属沿有界来源关系计算。终态无最终用量时仍为 partial，不能在最终答复生成前宣称“本轮全部已计量”。

查询返回目标/基线、对象及本次贡献、质量/反馈、投入与覆盖，并携带相同水位/价格摘要。`wi-report` 和 Stats 都消费这一条 query，不保留当前 Harness 直出报告与 collaboration 聚合两套业务计算。查询缓存和 Stats 发布物可重建，不授予事实权威。

正常 lifecycle 恢复包从这一结果携带已有目标、产出、修改理由、缺项及来源位置；轻量工作也消费同一结果而不补 Graph。前 WI 跨会话恢复使用原 context 引用。查询故障明确报缺口，不强迫用户复述已保存的内容，也不以失败状态授权后台重新工作。

### 9.4 替换、复用及实现证据

| 位置 | 实现动作 | 必须删除或退出的旧主路径 |
|---|---|---|
| ComputeCost `receipts.py` / query | 扩展目标、阶段产出/贡献、参与和 context 关联；复用现有账本事务、隐私与守恒 | “只有 WI 整体 Outcome 才算产出”的主模型；旧 schema 保留只读迁接 |
| `canonical_outcomes.py` / `outcome_projection.py` | 旧准确 Outcome 投影为其对象的质量事实，与阶段产出合并引用 | 将每次 review 或相同产物载体再次计件 |
| `cli.py` / `harness_query_report.py` / `scl_measurement.py` | 原生记录作为同一 query 的输入适配，不绕过统一计算 | Harness snapshot 直出与 Stats 聚合的业务分叉 |
| `attention.py` | 实现可审计片段、有限校准和明确缺测；旧 HAU 仅历史字段 | 用旧 HAU 权重代替时间、费用或价值判断 |
| Relay / 原生 Host / `measurements.py` / 恢复包 | 采集身份与事实保存从执行准入分离，贯通最终用量及恢复摘要 | 为记录普通参与而要求新的执行/人类批准；不得削弱实际工作权限 |
| Stats exporter / Swift 成本模块 | 消费统一产出与投入结果，支持同源展开及期间/累计区别 | 前端自己算成果/计价；无关 Stats 模块不改 |
| `compute-wi-cost` / `work-item-lifecycle` 正本 | 语义增量方法和正常恢复引用；共用同一命令 | 手工阶段附页作为长期接口、方法里复制另一套计算规则 |

源码层可行性依据：现有 Host 在无 WI 的 `identity` / `usage-range` 路径已能验证真实会话并读取有界来源；`UsageLedger.ingest_receipts` 已具备同锁原子批次、前驱校验和原样重放去重。新 `record-stage`、类型扩展、跨来源事件核销和恢复包尚未实现，必须由 rewrite/regression 提供失败先行回归与真实链路证据；这些现有原语不等于新功能已经通过。

实现前置：PULSE 获准工作区可用；CWA 两个 skill 正本必须先经正式 Host 仓库登记/安装和原生分配。当前逻辑 scope 不能替代该物理准入，不手改 active policy、不复制 skill 到 PULSE。

## 生产观察事实与准确版本接受

已整体采用的节点通过原生核心的生产 Git 观察流持久保存类型化 receipt 事务；
计量查询目录是可重建视图。`production_observations.v1` 最低读者特性阻止旧工具
把已采用的来源退回本地唯一写者。前 WI 记录不需要执行授权，不创建 WI；重复来源
保持原 fact 身份与水位，真实新增调用仍新增计量。采用原记录与来源登记在同一原库
锁下串行，原事务不删除；失败重试先读回同一事务，跨节点重建须逐项等价。

已验证前缀检查点（可丢弃的读取加速，不是事实源）：完整读取观察流后，读者在账本根下
私有目录 `observation-checkpoint`（0700，文件 0600，拒绝软链）原子写入清单与压缩分段。
清单记录 schema、派生逻辑版本（读者与核心校验源码的摘要）、账本绑定（namespace、
权威、ref）、已验证序号 N、第 N 批摘要、第 1..N 批包装对象及其分块对象的 Git 对象
指纹，以及自身摘要；分段按批保存元数据与每条事实的规范字节。下次读取只列 Git 树：
指纹相同才载入分段，并逐批用事实字节重算批次摘要、核对链和分段摘要；核心只读取并
校验 N+1 起的批次，以第 N 批摘要接链，最后核对 head。任一项不符、缺失、权限过宽或
校验异常都改为完整读取并重建检查点；同一 revision 下两条路径的事实、水位与快照摘要
逐项一致。本进程追加成功后同步推进检查点；写检查点失败只影响下次速度。

读取时紧凑表示（只改内存布局与查询内视图，不改写入口径、账本、检查点格式或
`receipt_snapshot()` 返回的全部事实列表）：一次读取内，相等的不可变值共用一个对象，
包括 payload 规范字节、时间戳、kind/producer、每个 evidence 引用和整条 evidence
元组；事实自身的 entity_ref/fact_ref 只复用已共用的等值对象。协作查询（`query
--collaboration`、`wi-report`、Stats 发布）在解出当前头后，把 producer、occurred_at
与 payload 字节都相同的 `registered_runtime_actor.v1` actor 头（同目标、执行者、
上下文、用量版本与生效时间，只差证据）读作一个代表头：代表取组内首个带证据的头，
身份证据 `actor_evidence` 仍列出组内全部原始 fact_ref。被任务归因或阶段链接指向的
actor 头不折叠；修正链与并发冲突在折叠前按原规则解出，冲突头不折叠。采集、去重
写入与其余读者仍逐条读取全部事实。开关：环境变量 `PULSE_COMPUTE_COST_ACTOR_FOLD=0`
或构造参数 `fold_actors=False` 关闭（默认开启）；两态的查询、`wi-report`、Stats
发布与采集写入逐字节一致。

`outputs.accepted` 只从同一候选的 final 记录中关联准确产物版本：人审 approve
与独立 verification accepted 或明确 waiver waive 同时存在。版本不符、intermediate
和 Agent 声明不能生成接受；矛盾同版本记录显示 unavailable。独立核验与豁免引用分别
保留，不把豁免显示成独立验真。数量沿用原声明按对象/单位分组，多个接受不重复计数。
Swift 与 exporter 都消费同一查询水位；旧的 unavailable 表达仍可读。
